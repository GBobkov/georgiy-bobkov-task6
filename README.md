# Издание

Компактное клиент-серверное приложение для приёма заметок, ведения сюжетов,
статистики и выпуска подтверждённых новостей. Сервер принимает несколько TCP
подключений, хранит данные в SQLite и не ждёт доставки поздравлений адресатам.

## Зависимости и сборка

Нужны Linux, компилятор C++20, CMake 3.20+, SQLite 3, OpenSSL Crypto и pthreads.

```sh
cmake -S . -B build
cmake --build build
```

## Запуск

Запустите сервер:

```sh
./build/edition server --bind 127.0.0.1 --port 5050 --db edition.sqlite
```

При первом запуске сервер попросит создать учётную запись редактора. Три
начальных клиента создаются автоматически с доверием `1.00`, `0.25` и `0.35`;
редактор задаёт им пароли перед первым входом.

Порог по умолчанию — `1.01`, период полураспада — 6 часов, поздравления
получают первые 3 источника. Редактор может изменить эти параметры.

В другом терминале запустите клиент:

```sh
./build/edition client 127.0.0.1 5050
```

Клиент спросит логин и пароль, затем покажет ожидающие поздравления и откроет
консоль команд. Роль назначается при создании учётной записи.

## Основные команды

Клиент отправляет заметку, смотрит личную статистику, получает уведомления и
может сменить собственный пароль:

```text
note request-001 "город" "Пожар на складе" 2026-10-18T16:00:00Z
stats
inbox
password
```

Время события указывается в UTC. Для повтора после потери квитанции отправьте
ту же команду с тем же ID запроса. Повтор получит квитанцию `дубль` и не создаст
нового голоса.

Редактор входит через тот же клиент под учётной записью с ролью `editor`:

```text
users
user-add client "Новый корреспондент" 0.20
user-password "Новый корреспондент"
user-trust "Новый корреспондент" 0.25
user-rename "Новый корреспондент" "Корреспондент N"
user-delete "Корреспондент N"
user-enable "Корреспондент N"
settings
set threshold 1.01
set half-life-hours 6
set congratulations 3
stories
story 1
publish 1
stats all
stats "Сахарисса Крипслок"
```

Созданная учётная запись не сможет войти до установки пароля. Удаление отключает
вход и сохраняет историю для статистики. Доверие фиксируется на первом голосе
клиента по сюжету; новые значения применяются к будущим голосам. Старые события
принимаются, но их вклад затухает от времени события. Выпуск доступен, когда
текущее доверие достигает порога; редактор запускает его вручную. Выпуск
необратим.

Доля в статистике — процент затронутых сюжетов, которые были выпущены. Средний
ранг и число сенсаций считаются по выпущенным сюжетам.

## Пример работы

При пороге `1.01` свежая заметка штатного корреспондента с доверием `1.00` ещё не
готова к печати. Редактор видит сюжет и его источники командой `stories` или
`story ID`. После заметки другого клиента с достаточным суммарным доверием
сюжет становится готов; редактор выполняет `publish ID`. Порядок подачи
фиксируется, поздравления записываются в очередь, а клиенты получают их при
следующем входе или команде `inbox`.

## Хранение и сеть

Сюжеты, заметки, квитанции, выпуски, настройки и очередь уведомлений сохраняются
в SQLite между запусками. Поздравления доставляются как минимум один раз и
подтверждаются клиентом; при обрыве до подтверждения они будут показаны снова.

По умолчанию сервер слушает только `127.0.0.1`. TCP-поток не шифруется, поэтому
для удалённого доступа используйте доверенную сеть или защищённый туннель.
