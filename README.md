# Издание — задача № 6

**Автор:** Бобков Георгий Эрнестович

## О проекте

«Издание» — компактное клиент-серверное приложение для сбора новостных заметок,
сведения их в сюжеты и выпуска подтверждённых новостей. Программа запускается
в двух режимах: сервер принимает подключения и хранит данные, консольный клиент
предоставляет команды корреспондентам и редакции.

Саморегистрации нет: первую учётную запись редактора создают при запуске
сервера, остальные записи добавляет редакция. В проекте используются C++20,
TCP-сокеты POSIX и SQLite.

## Зависимости и сборка

Для приложения нужны Linux, компилятор с поддержкой C++20, CMake 3.20 или новее,
SQLite 3, OpenSSL Crypto и pthreads.

```sh
cmake -S . -B build
cmake --build build -j2
```

Исполняемый файл появится в `build/edition`. Проверить общую справку можно
командой `./build/edition --help`.

## Запуск

В первом терминале запустите сервер:

```sh
./build/edition server --bind 127.0.0.1 --port 5050 --db edition.sqlite
```

Все параметры сервера необязательны. По умолчанию используются адрес
`127.0.0.1`, порт `5050` и файл базы `edition.sqlite`. Если в базе нет активного
редактора, сервер попросит задать его логин и пароль. Остановить сервер можно
сочетанием `Ctrl+C`.

Сервер по умолчанию слушает только локальный интерфейс. TCP-трафик не
шифруется; для удалённого доступа используйте доверенную сеть или защищённый
туннель.

При запуске сервер добавляет отсутствующие начальные клиентские записи без
паролей и не меняет существующие. Это стартовые записи для задания; остальные
учётные записи клиентов создаёт редакция:

| Логин | Доверие |
| --- | ---: |
| Сахарисса Крипслок | 1.00 |
| Избирательно Честный Тонни | 0.25 |
| Иногда Слепой Пью | 0.35 |

Редактор назначает им пароли командой `user-password`. Логин с пробелами в
командах заключайте в двойные кавычки, например:

```text
user-password "Сахарисса Крипслок"
```

В другом терминале запустите клиент:

```sh
./build/edition client 127.0.0.1 5050
```

Адрес и порт можно опустить — тогда клиент подключится к `127.0.0.1:5050`.
Клиент запросит логин и пароль, покажет ожидающие уведомления и откроет
интерактивную консоль. Редакторы и корреспонденты используют одну программу;
доступные команды определяются ролью учётной записи.

## Команды корреспондента

| Команда | Назначение |
| --- | --- |
| `note ID "РУБРИКА" "ТЕМА" YYYY-MM-DDTHH:MM:SSZ` | Подать заметку; время события указывается в UTC. |
| `stats` | Показать личную статистику. |
| `inbox` | Получить ожидающие поздравления. |
| `password` | Сменить свой пароль; клиент запросит его дважды. |
| `help` | Показать подсказку по командам. |
| `quit` | Завершить сеанс. |

Если рубрика, тема или ID заметки содержат пробелы, заключайте их в двойные
кавычки. ID заметки используется для безопасного повтора: повтор с теми же
данными вернёт квитанцию со статусом «дубль» и исходной оценкой доверия и
готовности, не создавая нового голоса. Каждая заметка получает квитанцию со
статусом «принята», «дубль» или «отказ» и причиной. Повторное использование ID
с другой рубрикой, темой или временем события будет отклонено без создания
новой заметки или голоса.

## Команды редактора

Редактор входит через тот же клиент под учётной записью с ролью `editor`.

| Команда | Назначение |
| --- | --- |
| `users` | Просмотреть учётные записи, роли, доверие и состояние доступа. |
| `user-add client LOGIN TRUST` | Добавить корреспондента с доверием от 0 до 1. |
| `user-add editor LOGIN` | Добавить редактора. |
| `user-rename LOGIN NEW_LOGIN` | Изменить логин, сохранив историю учётной записи. |
| `user-trust LOGIN TRUST` | Назначить клиенту новое доверие. |
| `user-password LOGIN` | Задать или сбросить пароль; клиент запросит новый пароль. |
| `user-delete LOGIN` | Отключить запись, сохранив заметки и статистику. |
| `user-enable LOGIN` | Повторно включить отключённую запись. |
| `settings` | Посмотреть параметры выпуска. |
| `set threshold VALUE` | Изменить порог доверия для публикации. |
| `set half-life-hours VALUE` | Изменить период полураспада доверия в часах. |
| `set congratulations COUNT` | Задать число первых источников для поздравления. |
| `stories` | Просмотреть сюжеты, их доверие и готовность к выпуску. |
| `story ID` | Просмотреть сведения о сюжете и полный порядок источников. |
| `publish ID` | Необратимо выпустить сюжет, достигший порога. |
| `stats LOGIN` | Просмотреть статистику одного клиента. |
| `stats all` | Просмотреть статистику всех клиентов. |

Команда `password` доступна и редактору — она меняет пароль текущей учётной
записи. Команды `inbox`, `help` и `quit` также доступны обеим ролям. Нельзя
отключить текущую учётную запись или последнего активного редактора. Новый
аккаунт не сможет войти, пока ему не зададут пароль.

Достижение порога переводит сюжет в состояние «готов к выпуску», но не
публикует его автоматически. Редактор выпускает сюжет отдельной командой
`publish ID`.

## Правила работы и проектные решения

- Клиент должен пройти авторизацию до отправки рабочих команд. Пароли хранятся
  не в открытом виде: сервер сохраняет случайную соль и PBKDF2-хеш.
- Один и тот же сюжет определяется точной парой «рубрика + тема». Заметки
  одного клиента учитываются в статистике, но голос за сюжет даёт только его
  первая принятая заметка.
- Заметки о событиях в прошлом принимаются, но их вклад сразу уменьшается с
  учётом возраста события. Для расчёта доверия будущая дата приравнивается ко
  времени приёма. Новая заметка по уже выпущенному сюжету отклоняется.
- Доверие фиксируется в момент первого голоса клиента за сюжет. Последующие
  изменения доверия в профиле применяются к следующим голосам клиента, в том
  числе к первому голосу за уже существующий сюжет; ранее зафиксированный голос
  не меняется. Вклад убывает экспоненциально от времени события; период
  полураспада по умолчанию — 6 часов.
- Порог по умолчанию — `1.01`. Готовность вычисляется при приёме заметки и
  просмотре сюжета; перед выпуском сервер повторно проверяет порог и доверие.
  Поэтому сюжет может перестать быть готовым, если доверие со временем упало.
- Порядок источников определяется временем получения сервером, а не временем
  события. При выпуске фиксируются ранги всех источников; отменить выпуск или
  изменить зафиксированный порядок нельзя. По умолчанию поздравляются первые
  три источника.
- Уведомления сохраняются в SQLite до подтверждения клиентом. Клиент
  подтверждает сообщение после вывода, поэтому при разрыве до подтверждения
  оно придёт снова.

Статистика считает отдельно заметки и сюжеты. «Принято заметок» — число
заметок клиента со статусом «принята». «Затронуто сюжетов» — число разных
сюжетов, в которые клиент подал принятую заметку. «Выпущено сюжетов» — число
этих сюжетов, за которые голос клиента попал в выпуск. Доля выпусков считается
как выпущенные сюжеты, затронутые клиентом, делённые на все затронутые им
сюжеты. Поэтому несколько принятых заметок одного клиента в одном сюжете
увеличивают счётчик заметок, но дают только один голос и не увеличивают счётчик
выпущенных сюжетов повторно. «Сенсации» — число выпусков, где клиент был первым
источником; средний ранг считается по выпущенным сюжетам. Каждый клиент видит
свою статистику, редактор — статистику любого клиента или всех сразу.

Сервер обслуживает несколько TCP-подключений параллельно, а операции с общей
базой сериализуются. SQLite выбран для компактного постоянного хранения; ключи
уникальности и транзакции защищают повторы запросов, голоса и выпуск от
дублирования. Очередь уведомлений не блокирует работу сервера, если клиент
отключён.

## Пример работы

При стандартном пороге `1.01` заметки корреспондента с доверием `1.00`
недостаточно для выпуска. Второй источник с доверием `0.25` поднимет сумму выше
порога, если вклад ещё не успел существенно затухнуть.

После назначения паролей войдите под записями «Сахарисса Крипслок» и
«Избирательно Честный Тонни» в двух сеансах клиента. Подставьте вместо
`ВРЕМЯ_UTC` текущее время в формате `YYYY-MM-DDTHH:MM:SSZ`. Узнать его можно
командой `date -u +%Y-%m-%dT%H:%M:%SZ`. Первый корреспондент отправляет:

```text
note note-001 "город" "Пожар на складе" ВРЕМЯ_UTC
```

Второй корреспондент отправляет заметку с теми же рубрикой и темой, но другим
ID:

```text
note note-002 "город" "Пожар на складе" ВРЕМЯ_UTC
```

Редактор смотрит ID сюжета в выводе `stories`, проверяет источники и выпускает
сюжет:

```text
stories
story ID
publish ID
stats all
```

После выпуска поздравления ставятся в очередь адресатов и показываются им при
следующем подключении или команде `inbox`.

## Структура проекта

- `src/client.cpp`, `src/net.cpp`, `src/common.cpp` — клиент, сетевой обмен и
  общие функции.
- `src/server.cpp` — запуск сервера и приём подключений;
  `src/server_connection.cpp` — авторизация и обработка команд клиента.
- `src/store.cpp` — схема SQLite, учётные записи и настройки;
  `src/store_workflows.cpp` — заметки, сюжеты и выпуск.
- `src/store_reporting.cpp` — статистика и уведомления; `src/store_sqlite.cpp`
  и `src/store_support.cpp` — работа с SQLite, паролями и вспомогательные функции.
- `include/` — заголовочные файлы интерфейсов и внутренних компонентов.
- `CMakeLists.txt` — сборка приложения.
